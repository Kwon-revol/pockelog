# PockeLog 연금저축·IRP 예상 세액공제 설계

## 1. 목적

PockeLog의 세금 탭에서 근로소득자가 연금저축과 IRP 납입 현황, 남은 공제 한도, 예상 세액공제 효과를 한눈에 확인할 수 있게 한다.

납입 내역을 세금 탭에 중복 입력하지 않는다. 가계부에서 `연금저축` 또는 `IRP` 지출 분류를 선택해 저장한 거래를 계산의 단일 원본으로 사용한다. 해당 거래는 사용자가 당장 쓸 수 있는 생활비에서 빠져나간 금액이므로 일반 지출 및 월별 지출 통계에도 포함한다.

1차 범위는 근로소득자의 연금저축·IRP 예상 세액공제에 한정한다. 향후 종합소득자와 의료비, 교육비, 월세 등 다른 연말정산 항목을 추가할 수 있도록 연도별 규칙과 항목별 계산기를 분리한다.

## 2. 범위

### 포함

- 근로소득자의 과세연도별 총급여 저장
- 연금저축·IRP 지출 분류의 자동 제공
- 로그인한 사용자가 직접 작성한 연금저축·IRP 거래의 연도별 자동 집계
- 연금저축 600만 원, 연금계좌 합계 900만 원 한도 진행률
- 소득세 공제 예상액, 지방소득세 감소 예상액, 두 금액의 합계
- 남은 공제 한도와 한도 초과 납입액 표시
- 연도별 납입 내역 조회와 기존 가계부 거래 수정 흐름 연결
- 개인 세금 정보에 대한 RLS 보호
- 모바일과 PC 반응형 화면
- 적용 연도, 계산 기준, 공식 근거 및 예상치 안내

### 제외

- 실제 환급액 또는 최종 결정세액 계산
- 종합소득자의 세액공제 계산
- 의료비, 교육비, 월세 등 다른 공제 항목
- ISA 만기자금의 연금계좌 전환 추가 한도
- 회사가 부담한 퇴직연금, 과세이연 금액 등 특수 납입액
- 금융기관 계좌 연동 및 자동 수집
- 세무 신고서 생성 또는 제출

## 3. 핵심 원칙

### 3.1 거래를 단일 원본으로 사용

연금 납입액을 별도 `tax_contributions` 레코드로 복제하지 않는다. 가계부 거래가 생성·수정·삭제·복원되면 세금 탭도 같은 원본을 다시 집계하므로 동기화 불일치가 발생하지 않는다.

### 3.2 사용자에게 연동 구조를 노출하지 않음

가계부 입력 화면에 `세금 탭에 반영`, `세액공제 납입` 같은 별도 스위치나 설명을 추가하지 않는다. 사용자는 다른 지출과 동일하게 `연금저축` 또는 `IRP` 분류만 선택한다.

### 3.3 개인 정보 분리

총급여와 계산 결과는 장부 구성원 관계와 무관하게 사용자 본인만 접근한다. 공동 장부의 거래 자체는 기존 장부 권한에 따라 구성원에게 보일 수 있지만, 세금 탭은 현재 로그인한 사용자가 직접 작성한 거래만 집계한다.

### 3.4 연도별 규칙 분리

금액 한도와 공제율을 화면 컴포넌트나 SQL에 산재시키지 않는다. 지원 과세연도별 규칙 객체와 순수 계산 함수를 두어 법 개정 시 새 규칙을 추가할 수 있게 한다. 규칙이 없는 연도는 가장 가까운 연도의 값을 임의로 적용하지 않는다.

## 4. 사용자 흐름

### 4.1 납입 등록

1. 사용자가 가계부에서 지출 내역 추가를 연다.
2. 분류로 `연금저축` 또는 `IRP`를 선택한다.
3. 날짜, 내용, 금액, 선택적 메모를 입력하고 저장한다.
4. 거래는 가계부 목록과 지출 통계에 포함된다.
5. 세금 탭에서는 거래일의 연도를 기준으로 작성자 본인의 납입액에 자동 포함된다.

세금 탭의 `납입 내역 추가` 동작은 기존 거래 입력 흐름을 열고 지출 유형과 선택한 연금 분류를 미리 선택한다. 별도의 납입 저장 폼은 만들지 않는다.

### 4.2 세금 탭 조회

1. 사용자는 과세연도를 선택한다.
2. 해당 연도의 총급여가 없으면 입력 안내를 확인한다.
3. 총급여 저장 후 공제율과 예상 세액공제 결과를 확인한다.
4. 연금저축 및 전체 연금계좌 진행률, 남은 한도, 초과 납입액을 확인한다.
5. 아래의 납입 내역을 최신순으로 조회한다.
6. 내역을 선택하면 기존 가계부 거래 수정 화면으로 이동하거나 같은 편집 UI를 연다.

### 4.3 수정·삭제·복원

- 날짜를 바꾸면 변경된 과세연도로 이동해 집계된다.
- 금액 또는 분류를 바꾸면 새 값으로 즉시 재계산된다.
- 휴지통으로 이동한 거래는 계산에서 제외한다.
- 복원한 거래는 다시 계산에 포함한다.
- 영구 삭제된 거래는 복구하거나 집계하지 않는다.

## 5. 분류 식별 설계

`categories`에 선택 가능한 내부 식별 열을 추가한다.

| 내부 코드 | 기본 표시 이름 | 거래 유형 |
|---|---|---|
| `pension_savings` | 연금저축 | `expense` |
| `irp` | IRP | `expense` |

내부 코드는 사용자 화면에 노출하지 않으며 일반 설정 기능으로 수정할 수 없다. 표시 이름, 색상, 순서, 활성 상태가 바뀌어도 내부 코드는 유지한다. 이름 문자열로 세금 항목을 판별하지 않으므로 이름 변경, 대소문자, 공백, 동명 분류의 영향을 받지 않는다.

장부 하나에는 내부 코드별 분류가 최대 하나만 존재하도록 조건부 고유 인덱스를 둔다. 새 장부를 생성할 때 두 기본 분류를 함께 만든다.

기존 장부 이전은 다음 순서로 수행한다.

1. 해당 장부의 지출 분류 중 공백과 대소문자를 정규화한 이름이 `연금저축` 또는 `IRP`와 일치하면 그 분류에 내부 코드를 연결한다.
2. 일치하는 분류가 없으면 새 분류를 생성한다.
3. 여러 후보가 생길 수 없는 현재 장부·유형·정규화 이름 고유 제약을 활용한다.
4. 마이그레이션을 다시 실행해도 중복 분류가 생기지 않도록 멱등성을 보장한다.

비활성 분류에 연결된 과거 거래도 집계한다. 사용자가 새 납입을 등록하려면 설정에서 해당 분류를 다시 활성화해야 한다.

## 6. 개인 세금 설정 데이터

과세연도별 개인 설정을 저장하는 테이블을 추가한다.

### `public.user_tax_profiles`

- `user_id uuid`: `auth.users(id)` 참조
- `tax_year integer`: 지원 과세연도
- `income_type`: 1차 버전은 `employment`
- `gross_salary bigint`: 근로소득자의 총급여액, 0 이상
- `created_at`, `updated_at`
- 기본 키: `(user_id, tax_year)`

조회·삽입·수정·삭제 정책은 모두 `user_id = auth.uid()`인 경우만 허용한다. 클라이언트가 다른 `user_id`를 보내도 저장할 수 없게 한다.

현재 원안에 있던 자유 형식 `tax_goals` 및 `tax_contributions`는 이번 기능에서 생성하지 않는다. 목표는 해당 연도의 법정 공제 한도에서 자동으로 정하며 납입액은 거래에서 계산한다. 향후 다른 절세 목표 관리 기능이 필요하면 세액공제 계산과 분리된 기능으로 다시 설계한다.

## 7. 개인별 납입 집계

납입 거래는 다음 조건을 모두 만족해야 한다.

- `transactions.created_by = auth.uid()`
- `transactions.type = 'expense'`
- `transactions.deleted_at is null`
- `transactions.occurred_on`이 선택 과세연도 안에 있음
- 연결된 분류의 내부 코드가 `pension_savings` 또는 `irp`

공동 장부 소유자가 다른 구성원이 작성한 거래를 수정할 수 있는 기존 권한은 유지한다. 수정된 거래는 원래 작성자의 세금 탭에 변경된 값으로 반영된다. 이는 세금용 사본을 만들지 않고 가계부 거래를 단일 원본으로 사용하는 결과다.

세금 탭용 서버 워크플로는 세션의 사용자 ID를 직접 사용한다. 사용자 ID를 URL이나 폼 입력으로 받지 않는다. 총급여 및 계산 요약은 공동 장부 구성원에게 제공하지 않는다.

사용자가 공동 장부에서 나가거나 제거돼도 본인이 작성한 연금 납입 내역은 개인 세금 기록의 근거이므로 집계에서 사라지지 않는다. 이를 위해 본인 작성 거래만 반환하는 제한된 세금 전용 데이터베이스 함수를 사용한다. 이 함수는 `auth.uid()`와 `created_by`가 같은 거래의 날짜, 분류 코드, 내용, 금액 및 편집 가능 여부만 반환하며 다른 구성원의 거래나 장부의 비공개 정보는 반환하지 않는다. 더 이상 장부 구성원이 아니면 해당 내역을 읽기 전용으로 표시하고, 장부명 대신 `이전 장부`로 표시한다. 현재 구성원인 거래만 기존 거래 수정 흐름으로 연결한다.

## 8. 계산 규칙

### 8.1 1차 지원 규칙

1차 버전은 2026년 과세연도만 지원한다. 현재 공식 기준에 따라 다음 규칙을 `kr-employment-pension-2026-v1`로 명시적으로 등록한다. 2025년 이전 또는 2027년 이후 연도는 해당 연도 규칙을 공식 자료로 검증해 별도 추가하기 전까지 계산하지 않는다.

- 연금저축 인정 한도: 6,000,000원
- 연금저축과 퇴직연금계좌 합계 인정 한도: 9,000,000원
- 총급여 55,000,000원 이하 소득세 공제율: 15%
- 총급여 55,000,000원 초과 소득세 공제율: 12%
- 지방소득세 효과: 소득세 공제 예상액의 10%

근거:

- [국가법령정보센터 소득세법 제59조의3](https://law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900470390)
- [국세청 근로소득 연금계좌 세액공제 안내](https://i.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7875&mi=6596)

### 8.2 계산 순서

```text
pensionEligible = min(pensionPaid, 6,000,000)
totalEligible = min(pensionEligible + irpPaid, 9,000,000)
incomeTaxRate = grossSalary <= 55,000,000 ? 0.15 : 0.12
incomeTaxCredit = floor(totalEligible * incomeTaxRate)
localIncomeTaxEffect = floor(incomeTaxCredit * 0.10)
estimatedTotalBenefit = incomeTaxCredit + localIncomeTaxEffect
```

연금저축 납입액이 600만 원을 초과하면 초과분은 전체 900만 원 한도를 채우는 금액으로도 사용하지 않는다. 예를 들어 연금저축 900만 원만 납입한 경우 공제 인정액은 600만 원이다.

계산 함수는 입력 금액을 정수 원 단위로 받고 다음 결과를 반환한다.

- 항목별 실제 납입액
- 연금저축 인정액
- IRP 인정액
- 전체 인정액
- 각 한도의 남은 금액
- 항목별 초과 금액
- 적용 공제율
- 소득세 공제 예상액
- 지방소득세 감소 예상액
- 총 절세 예상액
- 적용 규칙 버전과 공식 근거

### 8.3 예상치 안내

세금 탭은 다음 내용을 명시한다.

> 이 결과는 입력한 총급여와 PockeLog 납입 내역을 기준으로 계산한 예상치입니다. 실제 공제 및 환급액은 결정세액, 다른 공제 항목, 납입금의 적격 여부와 세법 변경 등에 따라 달라질 수 있습니다.

결과를 `환급액`으로 단정하지 않고 `예상 세액공제`, `예상 절세 효과`로 표현한다.

## 9. 화면 구성

### 9.1 상단

- 과세연도 선택
- 근로소득자 표시
- 총급여 입력·수정
- 규칙이 없는 연도의 지원 불가 안내

### 9.2 요약 카드

- 연금저축 납입액 / 600만 원과 진행률
- IRP 납입액
- 전체 납입액 / 900만 원과 진행률
- 공제 인정액과 남은 한도
- 한도 초과 납입액

### 9.3 예상 절세 결과

- 적용 소득세 공제율
- 소득세 세액공제 예상액
- 지방소득세 감소 예상액
- 총 절세 예상액

총급여를 입력하지 않았다면 공제율과 금액 대신 입력 안내를 표시한다. 납입 현황 자체는 총급여 없이도 보여준다.

### 9.4 납입 내역

- 선택 과세연도의 연금저축·IRP 거래를 최신순으로 표시
- 날짜, 장부명, 분류 표시 이름, 내용, 금액 표시
- 내역 선택 시 기존 거래 수정 흐름 사용
- `연금저축 추가`, `IRP 추가` 동작에서 기존 거래 폼을 사전 선택 상태로 열기
- 목록이 길어지면 기존 가계부와 같은 자동 추가 조회 방식 사용
- 목록 끝 문구는 표시하지 않음

### 9.5 반응형 구성

PC에서는 요약 카드와 예상 절세 결과를 넓은 그리드로 배치하고, 모바일에서는 세로 카드로 배치한다. 모바일에서도 계산 정보의 순서와 기능은 동일하게 유지한다.

## 10. 오류와 경계 상황

- 총급여 미입력: 계산하지 않고 입력 안내
- 음수 총급여 또는 금액 범위 초과: 서버 검증 오류
- 지원하지 않는 연도: 다른 연도 규칙을 대체 적용하지 않음
- 납입액 없음: 0원 상태와 시작 안내 표시
- 한도 초과: 기록은 유지하고 인정액과 초과액을 분리 표시
- 거래 수정 충돌 또는 저장 실패: 기존 거래 오류 처리 방식을 재사용
- 분류 이름 변경: 내부 코드로 계속 집계
- 분류 비활성화: 과거 내역은 집계하되 새 거래 선택지에서는 제외
- 거래 휴지통 이동: 즉시 집계 제외
- 거래 복원: 즉시 집계 재포함
- 세션 만료: 로그인 화면으로 이동
- 다른 사용자 세금 프로필 접근: RLS로 거부
- 공동 장부 탈퇴·제거: 본인 납입 내역은 유지하되 읽기 전용 및 `이전 장부`로 표시

## 11. 확장 경로

1차 기능 이후에는 같은 상위 구조 아래 항목별 계산기를 추가한다.

- 종합소득자: `income_type`과 종합소득금액 기준 규칙 추가
- 의료비: 대상자 관계, 총급여 대비 최저사용금액, 항목별 공제율 모듈
- 교육비: 대상자와 교육기관 유형별 한도 모듈
- 월세: 총급여·주택 요건·지급액 한도 모듈
- 기부금 및 보험료: 항목별 한도와 이월 규칙 모듈

각 모듈은 자신의 입력, 적격금액 계산, 한도, 공제율, 근거, 설명을 독립적으로 제공한다. 전체 연말정산 화면은 각 모듈의 결과를 조합하되 실제 결정세액을 계산하지 않는 한 `예상 공제 합계`로만 표시한다.

## 12. 검증 계획

### 계산 단위 테스트

- 총급여 55,000,000원과 55,000,001원의 공제율
- 납입액 0원
- 연금저축 6,000,000원 경계 및 초과
- 합계 9,000,000원 경계 및 초과
- 연금저축만 납입한 경우
- IRP만 납입한 경우
- 연금저축 9,000,000원만 납입한 경우의 인정액 6,000,000원
- 원 단위 내림 처리
- 지원하지 않는 과세연도

### 데이터베이스 및 권한 테스트

- 기존 분류 연결 및 없는 분류 생성
- 마이그레이션 재실행 시 중복 방지
- 내부 코드 중복 방지와 일반 사용자 수정 차단
- 본인 세금 프로필 CRUD 허용
- 다른 사용자 세금 프로필 CRUD 차단
- 공동 장부에서 거래 작성자별 집계 분리
- 공동 장부 탈퇴·제거 후 본인 납입 집계 유지와 다른 장부 정보 비노출
- 삭제·복원 거래의 집계 포함 여부

### 통합 및 화면 테스트

- 가계부에서 연금 분류 거래 생성 후 세금 탭 반영
- 금액·날짜·분류 수정 후 재계산
- 납입 내역에서 기존 거래 수정 흐름 연결
- 총급여 저장 후 공제율 및 예상액 표시
- 빈 상태, 한도 초과, 오류 상태
- PC 및 모바일 공개 화면 회귀 테스트
- 타입 검사, ESLint, 프로덕션 빌드

## 13. 완료 조건

- 사용자가 가계부에서 연금저축·IRP 분류로 지출을 기록하면 본인의 세금 탭에 자동 반영된다.
- 연금 납입은 일반 지출 및 월별 통계에 포함된다.
- 총급여와 납입액에 따라 소득세, 지방소득세, 총 예상 절세액이 분리 표시된다.
- 한도와 공제율의 경계 계산이 단위 테스트로 보장된다.
- 공동 장부 구성원이 다른 사용자의 총급여와 계산 결과에 접근할 수 없다.
- 기존 장부와 새 장부 모두 연금저축·IRP 분류를 중복 없이 사용할 수 있다.
- 지원하지 않는 연도와 실제 환급액의 불확실성을 사용자에게 명확히 안내한다.
- 향후 종합소득자 및 다른 연말정산 항목을 독립 계산 모듈로 추가할 수 있다.
